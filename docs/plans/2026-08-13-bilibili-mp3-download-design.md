# Bilibili MP3 流式下载设计

## 目标与范围

在 `/music` 搜索结果卡片中启用“转换 MP3”。第一版仅处理用户有权下载和转换的内容，每次处理一个视频，输出 192 kbps MP3，并限制音轨时长不超过 10 分钟。

## 视频与分 P 规则

接口只接受合法 BV 号，不接受任意 URL。服务端从 Bilibili 视频详情接口获取可信标题、CID、分 P 数量和时长。单 P 视频直接处理；多 P 合集第一版只处理第 1P，文件名使用第 1P 标题，并通过响应头告知前端这是合集首 P。10 分钟限制按实际处理的分 P 时长计算，不按合集总时长计算。

## 转换数据流

浏览器调用 `GET /api/bilibili/mp3?bvid=...`。服务端获取 DASH 播放信息，选择音质最高的可用音轨，再以带 Bilibili Referer 的 HTTP 请求读取音频流。源音频流直接写入 FFmpeg 标准输入，FFmpeg 从标准输出持续产生 MP3，不创建临时文件。

API 使用 Node.js Runtime，并设置适合 Hobby Fluid Compute 的最长执行时间。响应采用 `audio/mpeg`、附件文件名和禁用缓存的头部。浏览器逐块读取响应，显示已接收大小，完成后生成短期 Blob URL 并触发保存。用户断开连接时终止上游请求和 FFmpeg 进程。

## 安全与资源控制

接口限制 BV 号格式、音轨时长和并发转换数量；只允许 Bilibili 返回的受信音频 URL，并校验其协议为 HTTPS。文件名移除控制字符和操作系统保留字符。错误响应不泄露上游音轨地址、Cookie 或内部堆栈。

## 页面交互

每张卡片拥有独立的转换状态：准备、转换中、已下载或失败。同一时刻页面只允许一个下载任务，转换按钮显示已接收 MB；失败信息显示在对应卡片内。页面提示多 P 默认下载第 1P，并明确版权责任。

## 验证

单元测试覆盖 BV 号、时长、文件名、分 P 选择和音轨选择。API 使用短视频执行端到端转换，校验响应为 MP3 且文件头/FFprobe 可识别；随后运行新增文件 ESLint、TypeScript 和生产构建，并在桌面与移动宽度验证按钮状态。
