# Bilibili 音乐搜索设计

## 目标与范围

新增 `/music` 页面，让用户输入音乐关键词，从 Bilibili 搜索视频并查看结果。第一阶段只实现搜索和展示，不下载视频、不执行 FFmpeg 转换；结果卡片保留“转换 MP3”入口，明确标记为即将开放。

## 架构

浏览器只请求项目自己的 `GET /api/bilibili/search` 接口。API 校验 `keyword`、`page` 和 `pageSize` 后，在 Node.js Runtime 中请求 Bilibili 视频搜索接口，并把上游数据转换成稳定、精简的站内结构。这样可以避免浏览器跨域问题，也便于未来更换搜索实现或加入限流。

搜索按用户提交触发，不随输入实时请求。首屏加载 12 条，用户点击“加载更多”后继续请求下一页；每页最大 20 条。接口对相同查询使用短期缓存，请求 Bilibili 时设置 8 秒超时。

## 页面与交互

页面采用深色音乐工作台风格：顶部是品牌区和搜索框，结果区使用响应式卡片网格。每张卡片展示封面、标题、UP 主、视频时长、播放量和发布日期，并提供前往 Bilibili 的外链。加载、空结果、失败和加载更多均有独立状态；重复提交和重复加载会被禁用。

## 数据与错误处理

服务端会移除标题中的 HTML 标签、规范封面 URL、过滤缺少 BV 号的异常记录，并仅返回前端需要的字段。非法参数返回 400；Bilibili 拒绝访问、超时或响应结构异常返回 502/504，并向前端提供可读中文提示，不泄露内部错误栈。

## 后续 MP3 转换

后续在 Node.js Runtime 中使用打包的 FFmpeg 二进制。转换任务将限制视频时长和并发数，产物上传对象存储后返回下载链接；实现与搜索接口分离，以便未来把转换任务迁移到独立服务。只处理用户有权下载和转换的内容。

## 验证

为参数解析和 Bilibili 数据转换编写单元测试；运行 ESLint、TypeScript 检查和 Next.js 生产构建；本地启动页面后验证搜索、分页、空结果和错误状态，并进行桌面与移动宽度视觉检查。
